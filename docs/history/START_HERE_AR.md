# تشغيل DEGHEIDY QA74 Supervised T4

هذا إصدار مرشح، مبني على حزمة QA74 Fixed السابقة، وليس مشروعًا جديدًا. تم اختبار 194 اختبار Python و13 اختبارًا فرعيًا على CPU. لم يتم تدريب أوزان Qwen هنا، ولم يُقَس مستوى 8/10. ربط الإصدار السابق بتقييم 7.4 مأخوذ من تقريره؛ لم أتحقق مستقلًا من سجل التقييم الأصلي كاملاً.

## Colab T4 — بدون API
1. افتح `DEGHEIDY_QA74_SUPERVISED_T4.ipynb` في Colab واختر T4.
2. Stage 1: فك المصدر، تثبيت المكتبات، اختبارات، تدقيق بيانات التدريب.
3. Stage 2: اختياري: اختبار الأساس قبل التدريب. سجل WAV حقيقي بالنص المرجعي إن أردت اختبار الصوت.
4. Stage 3: راجع 140 مثالاً اصطناعيًا في `training/data/qa74_supervised.jsonl` (منها 20 مثالًا جديدًا للأخبار والأدلة). بعد المراجعة، اكتب REVIEWED في نافذة الإدخال لتأكيد بدء التدريب. تثبيت Unsloth ثم تدريب FP16 LoRA، rank 8، epoch واحدة، 768 tokens. تحفظ النتائج والأوزان وvalidation loss قبل وبعد. لا تستخدم واجهة الشات بالتزامن. T4 قد ينفد من الذاكرة؛ لا تعتبر الوصفة مضمونة، خفّض طول السياق أو rank إذا احتجت، وأعد التقييم. لا ترفع أسرارًا إلى GitHub.
5. Stage 4: اختيار الموديل الأصلي أو Adapter المدرب؛ اختبار جولتين منفصلتين بنفس إصدار الأوزان والكود. كل جولة تتضمن 10 حالات أصلية؛ ملف JSON يسجل الردود ومعلومات الإصدار، ولا يضع درجات تلقائية. راجع الردود ومصادرها والصوت، وحدد لكل حالة human_score من 0 إلى 10 وcritical_error true/false. لا تقم بتعديل الأدلة الأصلية. إن لم يتوفر WAV، الاختبار غير كامل ولا يمكن اعتماد الإصدار.
6. Stage 5: تشغيل Gradio بالنفس الإعدادات المختبرة. بدون تدريب يمكن تشغيل الأساس بعد Stage 1 مباشرة (USE_TRAINED=False).
7. Stage 6: التحقق من ملفين مختلفين تمت مراجعتهما. يلزم 8/10 لكل جولة، 8/10 للأخبار، صفر أخطاء حرجة، Stop وعودة الطلب، وصوت فعلي. تحقق يدوي من أن نتائج البحث والروابط صالحة؛ الاختبارات الآلية لا تثبت جودة الأخبار الحية.

## GitHub
ارفع المصدر في branch تجريبي أولًا. احفظ `training_manifest.json` و`adapter_config.json` و`adapter_model.safetensors` في artifact منفصل مناسب لحجم الأوزان؛ سجل SHA256 وإصدار base commit من التقرير. استخدم `DEGHEIDY_MODEL_REVISION` و`DEGHEIDY_QWEN_ADAPTER` في بيئة التشغيل، وثبت نفس إصدارات المكتبات التي نجحت في التقييم. بدون Adapter لن تكون النسخة المدربة. إذا أعطى Adapter أداء أقل، احتفظ بالأساس. لا تستخدم GitHub Pages لتشغيل Python GPU. لا تستبدل main قبل اجتياز التقييم.

تشغيل مباشر: `pip install -r requirements.txt` ثم `python app.py`. للـAdapter ثبت PEFT المتوافق مع بيئة الاختبار. التدريب لا يتطلب OpenAI API. لا توجد ملفات أوزان مدربة مرفقة؛ ستنشأ عند نجاح Stage 3.
